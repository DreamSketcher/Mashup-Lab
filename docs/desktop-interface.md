# Настольный интерфейс Mashup Lab

Экспериментальный интерфейс на PySide6 вызывает существующий
`quick-mashup` для сведения. Отдельная подготовка файлов использует FFmpeg
для преобразования формата и частоты; сам renderer и его SRC-контракт не меняются. Две панели источников
и компактная схема расположения вдохновлены общими принципами
[дек и микшера Mixxx](https://github.com/mixxxdj/manual/blob/main/source/chapters/user_interface.rst)
и [таймлайна Audacity](https://www.audacityteam.org/manual/timeline/); код,
изображения и тему этих проектов не копировали. Цветные полосы здесь — **границы
клипов по данным заголовков**, не waveform и не прослушивание. Нет перетаскивания
или полноценного DAW-редактора.

## Установка и запуск

На Windows запустите `Mashup-Lab.bat`: выберите **2** для подготовки
окружения, PySide6 и FFmpeg, затем **9** для открытия интерфейса. Пункт **1**
проверяет все компоненты; пункт **8** отдельно устанавливает или восстанавливает
интерфейс и FFmpeg. Для установки потребуются интернет и достаточно места. Python 3.11+ и полная распакованная
копия репозитория необходимы. Либо вручную в PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-gui.txt
.\.venv\Scripts\python.exe -m mashup gui
```

Linux/macOS (для Linux нужны системные библиотеки Qt и рабочая графическая
сессия; на минимальных системах дополнительно могут требоваться libGL, libEGL,
xkbcommon, dbus и библиотеки платформенного плагина Qt):

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-gui.txt
.venv/bin/python -m mashup gui
```

PySide6 и `imageio-ffmpeg` — **отдельные необязательные** зависимости GUI, `requirements.txt`
базового CLI не изменён. `requirements-gui.txt` выбирает PySide6 6.8.3 для Python 3.11–3.13 и
6.10.3 для Python 3.14, устанавливая также зависимости CLI; это не полный lock
зависимостей. PySide6 6.10.3 не поддерживает Python 3.15 и новее: для GUI
используйте Python 3.11–3.14. В metadata этих версий PySide6,
PySide6-Essentials, PySide6-Addons и shiboken6 указаны варианты `LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only`.
У Qt и всех бинарных компонентов есть собственные условия и возможная
коммерческая лицензия; конкретные wheels, native библиотеки, plugins, notices,
исходники и соответствие требованиям LGPL/дистрибуции необходимо проверить до
релиза. См. [Qt for Python](https://doc.qt.io/qtforpython-6/) и
[исследование лицензий](licensing-distribution-research.md). Установка для
разработки не является выбором лицензии проекта или подтверждением compliance.

## Использование

Слева находятся разделы **Мешап**, **Конвертация**, **Параметры** и **Трасса**;
каждый открывает своё содержимое в главном окне. Выбор файлов и папок
использует немодальный файловый диалог; настройки не открываются отдельными
модальными окнами.

### Подготовить несовместимый файл

1. В разделе «Мешап» у выбранного файла нажмите **В конвертер**, или откройте
   раздел «Конвертация» и выберите локальный исходник самостоятельно. FFmpeg
   может читать WAV, MP3, FLAC и другие форматы, которые поддерживает конкретная
   сборка; для файла с несколькими дорожками выбирается **первая аудиодорожка**.
2. Укажите имя **нового** WAV и выберите mono или stereo. Выход фиксирован как
   **48 000 Гц, 16-bit signed PCM WAV** для существующего renderer. Пока нет
   конвертации в 24-bit: FFmpeg может писать такой WAV в формате Extensible,
   который текущий renderer не принимает.
3. Нажмите **Конвертировать**. Дождитесь завершения или нажмите **Остановить**.
   Исходник не перезаписывается, существующий выходной файл не заменяется.
   При успехе выберите **Использовать как аудио 1/2** и проверьте границы
   клипа; координаты до/после преобразования частоты не равны по номерам frames.
   В случае ошибок посмотрите раздел «Трасса». Можно выбрать другой путь и
   повторить, если выход уже существует.

Это явная **отдельная файловая операция**, а не встроенный SRC рендерера и не
согласование D1–D6. Используется обработка FFmpeg по умолчанию; выбранная
конфигурация и версия записываются в трассу. Ресемплинг, 16-bit quantization и
сведение в mono/stereo меняют данные, могут изменить уровень или привести к
потерям/клиппингу. Прослушайте результат; true-peak и музыкальное качество не
проверяются. WAV сохраняется как отдельная копия и затем копируется в проект
при создании мешапа. Если приложение аварийно прервано, в целевой папке может
остаться скрытая `.mashup-convert-*` временная папка; при неудачном копировании
на файловой системе без hardlink может остаться неполный выходной файл. Их
нужно проверить вручную. Исходник остаётся без изменений.

### Создать мешап

1. Выберите два имеющихся **48 kHz PCM WAV** (обычный WAV, mono/stereo,
   signed integer 16/24/32 bit); используйте записи, на которые есть права.
2. При необходимости задайте диапазон в source frames, расположение на 4/4
   таймлайне (такт/доля/тик), gain, balance и fades в output frames. В разделе
   «Параметры» задайте BPM, разрядность результата и повторную проверку. BPM
   определяет только сетку размещения, не скорость музыки. По умолчанию оба
   полных файла начинаются одновременно. Схема интервалов примерная до проверки
   проекта; фактические кадры определяет план.
3. Укажите **новую** папку проекта, родительская папка должна существовать.
   Нажмите **Создать мешап**. Длительная работа идёт в дочернем процессе;
   приложение остаётся отзывчивым. Кнопка **Остановить** завершает процесс,
   после чего папка проекта может остаться неполной. Закрытие главного окна во
   время обработки блокируется: сначала дождитесь её или нажмите «Остановить».
4. По завершении нажмите **Открыть WAV**: файл откроется во внешней программе
   системы. В папке находятся `project.yaml`, копии источников и `mashup.wav`;
   старые файлы не перезаписываются. Повторный рендер в этом окружении включён
   по умолчанию и проверяет PCM hash. Peak и scale относятся к sample-peak,
   не true-peak/LUFS. Подробнее — [CLI-руководство](two-audio-cli.md).

Автоматической синхронизации, детекции BPM, time-stretch, pitch-shift и
шумоподавления нет. Короткие файлы предпочтительны: renderer хранит полные
исходники и результат в памяти. Пользователь должен сам оценить звучание,
щелчки и баланс. Выбор лицензии проекта и согласование D1–D6 остаются открыты.

### FFmpeg и условия распространения

`requirements-gui.txt` устанавливает `imageio-ffmpeg==0.6.0`: это BSD-2-Clause
Python-обёртка, а wheels включают **отдельный исполняемый FFmpeg**, с иными
условиями. Он не помещается в Git. В просмотренном Linux wheel версия 7.0.2
показывает `--enable-gpl --enable-version3`, `ffmpeg -L` сообщает GPL v3 or
later; в просмотренном Windows x64 wheel исполняемый FFmpeg 7.1 содержит строки
тех же флагов. Точный состав и лицензия зависят от платформы/сборки: см.
[срез и release gate](licensing-distribution-research.md). Запуск через
subprocess сам по себе не решает юридический вопрос поставки. Прежде чем
распространять сборку, нужны проверка лицензий/исходников конкретного бинарника,
notices, транзитивных компонентов и юридический анализ. License проекта не
выбрана. `IMAGEIO_FFMPEG_EXE`, если задан пользователем, может переопределять
бинарник; фактический исполняемый путь и конфигурация фиксируются в трассе.

## Локальная трасса

Каждый запуск GUI создаёт отдельный `~/.mashup-lab/traces/session-*.jsonl`
(на Windows: `%USERPROFILE%\.mashup-lab\traces\`). Путь показан в окне;
кнопка **Открыть папку логов** позволяет найти текущую и предыдущие сессии
после закрытия приложения. Каждая строка JSON содержит UTC timestamp и имя
события. Пишутся запуск, выбранные файлы и параметры, действия элементов,
открытие диалогов/их результат, запуск процесса, диагностические события
проверки источников/копирования/плана/декодирования/сведения/экспорта,
повторный рендер, запуск/прогресс/завершение или отмена FFmpeg, его stderr,
исполняемый путь и аргументы, ошибки, коды завершения, закрытие и доступные
необработанные Python/Qt сообщения. Трасса сбрасывается в файл на каждом событии.
Звуковые PCM-данные не записываются.

**Граница наблюдаемости:** это инструментированная трасса приложения и
запущенного им `quick-mashup`, а не запись абсолютно всех событий ОС, Qt,
внешнего проигрывателя или внутренней работы нативных DSP-библиотек. Движение
мыши, каждое нажатие клавиши, внутренние сэмплы и обычные независимые вызовы
CLI не трассируются. Изменения текстовых полей фиксируются после завершения
редактирования, числовых — по изменению значения. Аварийное завершение процесса,
потеря питания, сбой загрузки Qt или невозможность записи могут оставить трассу
неполной; отсутствие записи не доказывает, что действия не было. Ошибка
создания/записи лога отображается в окне, обработка не блокируется. При ошибке
импорта GUI путь трассы, если удалось создать файл, выводится в консоль.
Если пункт 8 не может установить PySide6 или FFmpeg, проверьте версию Python в `.venv`:
`.venv\Scripts\python.exe --version`; файл `requirements-gui.txt` должен быть
актуальным. После обновления репозитория повторите пункт 8, затем 9; существующую
`.venv` удалять не требуется.

Трасса может содержать **имена файлов, полные пути, параметры, ошибки и хеши**.
Она сохраняется локально, никуда не отправляется автоматически, не имеет
автоматической ротации/удаления и может расти. Перед передачей третьим лицам
проверьте её и удалите чувствительные сведения; пользователь может вручную
удалить ненужные файлы трассы после закрытия GUI. Доступ к логам определяется
правами локальной системы. Лог не является защитой, аудиторским доказательством,
render manifest или доказательством детерминизма.

## Проверки

Автоматизированные smoke-тесты в `.github/workflows/gui.yml` используют Qt
`offscreen` и небольшие искусственные WAV; проверяют создание окна, выбор
значений, рендер через процесс, успешную трассу и ошибку неподдерживаемой частоты.
Они не заменяют ручную проверку визуального вида, звукового проигрывания,
диалогов файлов и кириллицы на реальных Linux/Windows/macOS. Текущий статус
конкретного workflow и ОС следует проверять отдельно; участие теста в workflow
само по себе не означает успешный запуск.

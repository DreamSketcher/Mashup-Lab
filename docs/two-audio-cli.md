# Два аудиофайла → экспериментальный мешап

Это быстрый способ **создать редактируемый проект и выполнить существующий
renderer**. Никакой автоматической музыкальной синхронизации, определения BPM,
подбора тональности, разделения вокала или изменения темпа нет. Первое
прослушивание и творческие решения — за вами.

## 1. Подготовьте два источника

Используйте свои записи или материалы, на переработку и распространение которых
у вас есть разрешение. Для текущего renderer нужны **непустые 48 kHz WAV**,
mono или stereo, обычный несжатый signed integer PCM **16/24/32 бит**, не
WAVE_FORMAT_EXTENSIBLE. Ресемплинг, MP3, AAC и float WAV напрямую не
поддерживаются. Если файлы в другом формате, заранее подготовьте совместимые
копии внешним инструментом на своё усмотрение: это отдельная операция, не SRC
Mashup Lab. `duration_ratio` остаётся 1, `pitch_semitones` — 0.

При подготовке вокала и инструментала вручную выберите записи с подходящими
темпом и тональностью; программа их не проверяет. Начните с коротких фрагментов:
текущий renderer загружает **все полные исходники и итоговый микс в память**.

## 2. Подготовьте окружение

Из корня репозитория, Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

На Windows можно сначала выбрать подготовку окружения в `Mashup-Lab.bat` (см.
[инструкцию](windows-launcher.md)). В PowerShell из корня репозитория
команды ниже запускаются через `.\.venv\Scripts\python.exe` вместо
`.venv/bin/python`. Пути с пробелами берите в кавычки. Сам пункт лаунчера для
создания двухфайлового проекта не добавлен; используется команда напрямую.

## 3. Создайте проект и WAV

```sh
.venv/bin/python -m mashup quick-mashup "audio 1.wav" "audio 2.wav" --project-dir "my-mashup" --verify-repeat
```

PowerShell:

```powershell
.\.venv\Scripts\python.exe -m mashup quick-mashup "audio 1.wav" "audio 2.wav" --project-dir "my-mashup" --verify-repeat
```

Команда **копирует** WAV, составляет `project.yaml`, проверяет проект/источники,
вычисляет план и рендерит `mashup.wav`. `--project-dir` должен быть новым,
родительская папка должна существовать. Ничего существующего не перезаписывается.
Если создание не завершилось, новая папка может остаться неполной: изучите её
перед удалением или выберите другое новое имя для повторной попытки.

По умолчанию оба файла используются целиком, начинаются одновременно с такта 1,
центральный balance, gain 0 dB, без fades, output stereo 24-bit. Временная сетка
проекта — 4/4 и 120 BPM: это **только настройка разметки**, она не изменяет BPM
исходного аудио. Автоматического распознавания начала такта нет; наложение
может музыкально не совпасть. Используйте разные gain и слушайте результат.

Итоговая папка:

```text
my-mashup/
  project.yaml       # все решения, редактируется вами
  sources/audio1.wav # копии исходников; оригиналы не меняются
  sources/audio2.wav
  mashup.wav         # слушайте этот файл
```

В stdout — JSON: пути, точный план, пересечения и результат рендера. `peak` —
пик смеси **до** peak protection, `scale` — применённое ослабление (1 означает,
что оно не потребовалось), `pcm_sha256` — хеш PCM-данных, не всего WAV-файла.
Опция `--verify-repeat` рендерит ещё раз во временный файл и сравнивает PCM
хеш и параметры в **этом окружении**, затем удаляет временную копию. Поле
`repeat_pcm_match` — `true` при совпадении и `null` без проверки; несовпадение
возвращает ошибку. Это не гарантия битового совпадения между разными машинами,
версиями или сборками и не render manifest.

## 4. Настройте расположение и баланс вручную

```sh
.venv/bin/python -m mashup quick-mashup "vocal.wav" "instrumental.wav" \
  --project-dir "mix-02" --bpm 120 --bar2 2 --beat2 1 \
  --gain1 -6 --gain2 -9 --pan1 -0.2 --pan2 0.2 \
  --fade-in1 240 --fade-out1 2400 --bit-depth 16 --verify-repeat
```

Здесь второе аудио начинается со второго такта, 0.005 с fade-in и 0.05 с
fade-out у первого на 48 kHz. Для каждой дорожки доступны `--bar1/2` (от 1),
`--beat1/2` (1–4), `--tick1/2` (0–959), `--gain1/2` (−120…+24 dB),
`--pan1/2` (−1…+1; balance) и `--fade-in1/2`, `--fade-out1/2` в **frames**.
По умолчанию полный исходник; `--start1/2` и `--end1/2` задают полуинтервал
source frames, конец не включён; например `--start1 48000 --end1 144000`
выбирает с 1 до 3 секунд. Fade не может быть длиннее выбранного клипа.
Смотрите все параметры: `.venv/bin/python -m mashup quick-mashup --help`.

Проверьте переходы и баланс на слух; по желанию измените `project.yaml` и
сохраните новый WAV без перезаписи старого:

```sh
.venv/bin/python -m mashup validate my-mashup/project.yaml
.venv/bin/python -m mashup plan my-mashup/project.yaml
.venv/bin/python -m mashup render my-mashup/project.yaml -o my-mashup/revision.wav
```

При изменении копий исходников обновлять проект автоматически нельзя: hash и
метаданные больше не совпадут, проект необходимо явно пересоздать или
осознанно обновить. При других версиях/системах выход может отличаться.

## 5. Прослушайте и зафиксируйте наблюдения

* Проверьте границы и длительность по JSON `plan`; прослушайте начало, конец,
  места наложения и переходы на наличие пропусков и щелчков. Наша команда не
  выполняет автоматическую диагностику слышимых артефактов.
* Проверьте левый/правый канал и баланс. `peak`/`scale` показывают работу
  **sample-peak** защиты, а не true-peak или LUFS; они не доказывают отсутствие
  слышимых искажений или межсэмпловых пиков.
* Для повторяемости включите `--verify-repeat`; сравнивайте PCM hash только
  при одинаковом проекте, источниках и окружении. Запишите версии Python,
  NumPy, soundfile/libsndfile и ОС, а также субъективные замечания.
* Если не устраивают звучание или стыки, скорректируйте параметры вручную;
  SRC, изменение темпа/тональности и продвинутая семантика границ ещё не
  реализованы. Никакое музыкальное качество автоматически не гарантируется.

## Первые проверки на реальных записях

На Linux Python 3.11.2 / NumPy 2.4.6 / soundfile 0.14.0 / libsndfile 1.2.2,
PyYAML 6.0.3 выполнены два коротких **технических** микса с образцами Bart
Massey: acoustic guitar `gc.wav`, synthesizer `synth.wav` и одиночная спетая
нота `voice-note.wav`. Их [источник и указание CC0](https://github.com/pdx-cs-sound/wavs/blob/ed5ebcbbbc2d11f0adddc9b50b78d581c29f738c/README.md)
(если не указано иное), точные SHA-256 и команды — в файлах `README.txt` и
`report.json` соответствующих результатов. Оригинальные файлы и результаты не
добавлены в Git.

* Гитара + синтезатор: 5 с, оба с начала, gain −6/−9 dB, fades, 240000 frames;
  peak до защиты 0.4411, scale 1, повторный PCM hash совпал.
* Гитара + одиночная спетая нота: 3 с, голос со второй доли 120 BPM, balance
  −0.3/+0.3, gain −6/−9 dB, fades; 144000 frames, пересечение `[24000,91257)`,
  peak 0.3073, scale 1, повторный PCM hash совпал.

Результаты прочитаны как 48 kHz stereo 24-bit WAV, полных по длительности;
прослушивание, субъективный анализ артефактов и полноценная композиция **не
проводились**. Это музыкальные сэмплы, а не готовые вокальные и инструментальные
дорожки. Для первых настоящих композиций нужны подходящие исходники и ручная
музыкальная оценка пользователем.

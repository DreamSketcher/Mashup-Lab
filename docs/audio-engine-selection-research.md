# Разделение и анализ аудио: результаты исследования

## Текущий статус

Разрешение пользователя на **локальную обученную модель** для отдельной
подготовки получено; это не изменение рендерера или его неутверждённых правил
D1–D6. Пока **нет встроенного отделения вокала, музыки или шумоподавления**.
Нельзя называть модель «лучшей» без измерений и прослушивания на примерах.

Наиболее подходящий кандидат для изучения — [audio-separator](https://github.com/nomadkaraoke/python-audio-separator),
MIT-обёртка с архитектурами MDX, VR, Demucs и другими. Для первого эксперимента
подходит UVR MDX-Net `UVR-MDX-NET-Inst_HQ_3.onnx`: две дорожки, код и модель
не являются двигателем Mashup Lab. По данным GitHub API файл занимает 66 759 214
байт. [UVR](https://github.com/Anjok07/ultimatevocalremovergui#license) указывает
MIT для кода и просит у интеграторов своих моделей соблюдать MIT и указывать
авторов UVR; выяснить принадлежность и условия **конкретного** файла и всех
производных перед распространением. Не переносить это заявление на чужие
модели. Например, автор [Demucs прямо указал](https://github.com/facebookresearch/demucs/issues/327#issuecomment-1134828611),
что его веса не покрыты MIT и предоставлены для научных целей.

`audio-separator` 0.48.0 (PyPI metadata) исключает Python 3.14.1, который может
использоваться в существующем окружении пользователя. Имеет значительный набор
зависимостей (включая PyTorch), требуется проверить загрузку, размер, версию
CPU/ускорителя и транзитивные лицензии. Это не означает, что движок в целом не
работает на других версиях. В текущем sandbox загрузка модели через
`github.com/TRvlvr/model_repo/releases/...` перенаправляет на
`release-assets.githubusercontent.com`, доступ к которому заблокирован;
фактическую работу модели и качество здесь проверить не удалось. GitHub API не
предоставил digest для данного актива; нельзя использовать непроверенный хэш.

Дальнейшая работа: отдельное окружение с поддерживаемым Python (не ломать GUI
3.14.1); явная установка по согласию, проверка размера и происхождения весов,
CPU-first тестирование на Windows с реальными аудио, операции отмены/трассы,
временная папка и сохранение новых результатов без перезаписи, импорт в конвертер
48 kHz. Нужно сравнить несколько лицензированно пригодных моделей на реальных
композициях и оценить на слух/измерениями, а не обещать отсутствие артефактов.
Удаление шума и реверберации — отдельные задачи и модели, не следуют автоматически
из отделения вокала. Выбор лицензии проекта, FFmpeg и всех условий поставки
остаётся открытым до релиза.

## Анализ BPM и тональности

Используются отдельные внешние библиотеки без изменения PCM исходников:
[librosa 0.11 beat tracker](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)
и [music-key-detector](https://github.com/mrueda/music-key-detector), MIT,
зафиксирован по коммиту `63b369dfffd5441ca0fa2db31b0c41e075377c20` и SHA-256
архива в requirements. Это оценки, не гарантии; анализ ограничен 90 секундами,
ручное подтверждение пользователем обязательно. Тональность не определяет
еднозначно гармоническую совместимость. Тест на синтетическом аккорде до мажор
проверяет интеграцию, но не демонстрирует точность на песнях.

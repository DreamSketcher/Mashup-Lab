# Разделение и анализ аудио: результаты исследования

## Текущий статус

По решению пользователя локальная обученная модель применяется только при
отдельной файловой обработке, не в renderer и не как решение по D1–D6.
Используются [audio-separator 0.41.1](https://github.com/nomadkaraoke/python-audio-separator)
(MIT, обёртка для UVR) и UVR MDX-Net `UVR-MDX-NET-Inst_HQ_3.onnx` как первая
модель вокал/инструментал. Это практический вариант, **не доказанный лучший**:
качество на композициях пользователя и сравнение с другими моделями не исследовано.
Функция оценивается на слух и может создавать артефакты. Она не предназначена
для отдельного удаления шума, эха или реверберации; MDX-параметр дополнительного
прохода не следует трактовать как отдельный механизм реставрации.

Модель (66 759 214 байт) скачивается в пользовательский кэш из UVR model_repo;
SHA-256 `317554b07fe1ea5279a77f2b1520a41ea4b93432560c4ffd08792c30fddf9adc`.
Хеш получен при загрузке GitHub Actions и совпадает с [независимо опубликованным
LFS pointer](https://huggingface.co/seanghay/uvr_models/blob/main/UVR-MDX-NET-Inst_HQ_3.onnx);
это контроль целостности, не доказательство авторства или условий лицензии.
Необходимые JSON-данные конфигурации загружаются из `TRvlvr/application_data`
по фиксированному commit `3826b05b570dbd4fbedbc807758803b35348ba1b` и также
проверяются по SHA-256. Никакие веса и аудио не хранятся в Git проекта.

Проверенный UVR engine 0.41.1 помещается в отдельное окружение Python 3.12;
это не меняет установленный пользователем Python 3.14. Вместе с MDX моделью
движок не оценивает BPM/тональность: на странице обработки отдельно доступны
анализаторы, указанные ниже. В Windows CI тестируется CPU-запуск реальной модели на очень коротком
синтетическом сигнале; это не оценка качества.
Публикация выходных WAV — отдельная 44.1→48 kHz FFmpeg-конвертация после
работы модели, не SRC renderer.

### Лицензии

[UVR](https://github.com/Anjok07/ultimatevocalremovergui#license) указывает MIT
для кода и просит интеграторов своих моделей соблюдать MIT и указывать авторов
UVR: Anjok07 и aufr33. Нужно отдельно подтвердить применимость к именно этому
файлу, доступность исходников/условий и соблюдение всех требований перед
распространением. Условия сторонних моделей нельзя предполагать одинаковыми:
автор [Demucs указывает](https://github.com/facebookresearch/demucs/issues/327#issuecomment-1134828611),
что его веса не покрыты MIT и предоставлены для научных целей. Нужен аудит
транзитивных лицензий Python, PyTorch, ONNX Runtime и бинарников FFmpeg. Лицензия
проекта не выбрана; использование при разработке не означает разрешения на релиз.

## Анализ BPM и тональности

Используются отдельные внешние библиотеки без изменения PCM исходников:
[librosa 0.11 beat tracker](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)
и [music-key-detector](https://github.com/mrueda/music-key-detector), MIT,
зафиксирован по коммиту `63b369dfffd5441ca0fa2db31b0c41e075377c20` и SHA-256
архива в requirements. Это оценки, не гарантии; анализ ограничен 90 секундами,
ручное подтверждение пользователем обязательно. Тональность не определяет
еднозначно гармоническую совместимость. Тест на синтетическом аккорде до мажор
проверяет интеграцию, но не демонстрирует точность на песнях.

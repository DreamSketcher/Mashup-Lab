# Windows: запуск Mashup Lab

Лаунчер предназначен для Windows 10/11 с Windows PowerShell 5.1. Он запускается
обычными правами, без администратора. Нужен Python **3.11 или новее** с модулем
`venv` и pip; для первоначальной установки пакетов нужен интернет. Доступность
колёс зависимостей зависит от версии Python и платформы. Установите Python с
[python.org](https://www.python.org/downloads/windows/), разрешив установку
Python Launcher (`py`) или добавление Python в PATH. Перезапустите лаунчер.

1. Скачайте и распакуйте весь репозиторий, не один BAT-файл. Дважды щёлкните
   `Mashup-Lab.bat`. Можно запустить и из другого рабочего каталога.
2. Выберите **2**, чтобы создать `.venv` внутри репозитория и установить
   зависимости из `requirements.txt`. Глобальная установка не используется.
   Повторный запуск проверяет хеш requirements, импорты и `pip check`; если всё
   в порядке, повторная установка не выполняется. Пункт **1** проверяет среду.
3. Подготовьте `project.yaml` по [описанию формата](project-format-specification.md),
   указав реальные пути, SHA-256 и метаданные исходных WAV. Пункты **3** и **4**
   проверяют проект и показывают план в консоли. Пустой ввод отменяет действие.
4. Выберите **5**, введите путь к проекту и имя **нового** выходного WAV. Пути
   могут быть абсолютными; относительные отсчитываются от каталога репозитория.
   Имя в кавычках при копировании из проводника допустимо. Результат находится
   по указанному пути; родительская папка должна существовать. Существующие файлы
   не перезаписываются даже после подтверждения: выберите новое имя. SHA-256 PCM,
   пиковый уровень и масштаб выводятся в консоль, но manifest пока не создаётся.
5. **6** открывает эту инструкцию в Блокноте, **7** завершает работу.

Экспериментальный рендер принимает только обычные PCM WAV 48 кГц, моно или
стерео, с исходной разрядностью 16/24/32 бита. `duration_ratio` должен быть 1,
`pitch_semitones` — 0: ресемплинга, растяжения и изменения высоты пока нет.
Выход — стерео PCM 16/24 бита. Рендер хранит данные в памяти; используйте
небольшие проекты. Сравнение хешей повторных запусков относится к одинаковому
окружению, а не гарантирует идентичность между разными компьютерами.

## Если что-то пошло не так

- **Python не найден или слишком старый:** установите поддерживаемую версию и
  перезапустите окно. Проверьте, что `py` или `python` доступны в PATH.
- **Ошибка установки:** проверьте соединение, права записи в каталог репозитория
  и текст pip. Пункт 2 можно повторить. Прокси и корпоративные ограничения могут
  потребовать отдельной настройки. Лаунчер не удаляет повреждённую `.venv`;
  после диагностики пользователь может самостоятельно убрать её и повторить.
- **Ошибка CLI:** проверьте путь, содержимое проекта, хеш и параметры WAV. Текст
  Python и код ошибки остаются видимыми. Пустой ответ отменяет ввод, а не рендер.
- **Кириллица отображается неверно:** используйте современный Windows Terminal
  или стандартную консоль с шрифтом, содержащим кириллицу. Лаунчер включает UTF-8
  для консольного ввода/вывода и Python на время своей работы; глобальные настройки
  не меняются. Проверка на конкретной русскоязычной системе всё равно необходима.
- **Файл результата существует:** укажите другое имя. Исходники и проект никогда
  не должны использоваться как путь результата.

Лаунчер выполняет локальный код репозитория и установку пакетов через pip;
используйте только доверенную копию проекта. Он не является защитной песочницей.
